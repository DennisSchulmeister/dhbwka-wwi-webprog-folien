Streng genommen ist jede interaktive Webanwendung, die nur einmal beim Aufruf eine komplette HTML-Seite vom Server lädt und ab dann mit JavaScript im Browser läuft, eine Single Page App. Gemeint ist, dass nach dem ersten Aufruf nur noch Rohdaten oder Seitenfragmente vom Server abgeholt werden, die eigentliche Seite im Browser aber bestehen bleibt und zu keinem Zeitpunkt neugeladen wird.

Gute Single Page Apps ändern daher jedem Wechsel der Ansicht die in der Adresszeile des Browsers angezeigte URL und werten diese aus, um bei einem Aufruf der Anwendung sofort an die richtige Stelle zu springen. Das erhöht den Nutunzgskomfort und vereinfacht oft sogar den Quellcode, da die gesamte Navigation an zentraler Stelle abgehandelt werden kann. ♻️ Und auch die Anzeige einer Fehlerseite bei dem Versuch, eine unbekannte URL aufzurufen, lässt sich mit ganz einfach realisieren.

Die Zuordnung der darzustellenden Ansicht zu einer URL wird Routing und die Komponente, die diese Zuordnung vornimmt, wird Router oder URL-Router genannt. Single Page Apps nutzen daher einen „Single Page App Router” (kurz SPA-Router), der genau diese Aufgabe übernimmt. Jedes auf die Entwicklung von Single Page Apps spezialisierte Framework bringt einen solchen Router mit. Wie sich herausstellt, lässt sich dieser aber auch ohne Framework sehr einfach selbst realisieren, wenn man dabei auf den alten Trick zurückgreift, dass der Browser eine Seite nicht neu lädt, sofern sich an der URL nur der Anker, also der Teil nach dem ersten #-Zeichen, ändert. Die bereits fertig ausprogrammierte Klasse Router in dieser Aufgabe, zeigt wie das geht.

Mit etwas mehr Logik lassen sich mit derselben Technik auch URLs ohne #-Zeichen behandeln. Dies setzt allerdings einen entsprechend konfigurierten Webserver voraus, der immer den HTML-Code der Startseite liefert, auch wenn scheinbar ein Unterverzeichnis angefragt wurde. Anstelle des hashchange-Events müsste dann das popstate-Event behandelt werden.

Die Nutzung der Klasse ist relativ leicht. Sie muss beim Laden der Seite instantiiert und mit einer Liste von URL-Routen versorgt werden. Jede Route beseht dabei aus einem regulären Ausdruck zum Matchen der URL sowie einer Funktion, die den angezeigten Inhalt verändert. Der Aufruf der start()-Methode führt dann dazu, dass die aktuelle URL ausgewertet und auf jede zukünftige URL-Änderung reagiert wird.

Soll innerhalb der Anwendung die Ansicht gewechselt werden, kann das ab diesem Moment entweder durch Überschreiben von location.hash in JavaScript oder durch einen Link in HTML ausgelöst werden:

location.hash = "other"; <a href="#/other/">Ansicht wechseln</a>

Du musst lediglich die Router-Klasse wie oben beschrieben initialisieren und ein paar alternative Ansichten mit Verlinkungen untereinander realisieren. 🔗 Wie das geht, steht wie immer als Kommentar im Quellcode.

URL-Routing ist enscheidung für eine gut gemachte Single Page App. Denn dadurch können die Unterseiten der Anwendung direkt eine URL aufgerufen und somit zum Beispiel als Link per Mail verschickt oder als Lesezeichen gespeichert werden. Grundregeln für guten JavaScript-Code

  • Leserlicher, gut kommentierter Code ist auch in JavaScript King!
  • Nutze modernes JavaScript (ES6 oder neuer) anstelle veralteter Techniken.
  • Ignoriere deshalb alle JavaScript-Tutorials von vor 2015. Sie sind alle veraltet.
  • Nutze keine globalen Variablen, wenn es nicht absolut sein muss.
  • Deklariere lokale Variablen immer mit let oder var.
  • Verwende in neuem Code jedoch immer let anstatt var.
  • Nutze die Pfeilsyntax für Funktionen anstelle von function.
  • Nutze function nur für globale nicht-anonyme Funktionen.
  • Vergleiche zwei Werte möglichst immer mit === anstatt mit ==.
  • Dadurch sind zweite Werte nur dann gleich, wenn sie auch denselben Typ besitzen.
  • Beschäftige dich mit Promises und nutze sie wo sinnvoll.
  • Nutze async und await, um die Arbeit mit Promises zu vereinfachen.
  • Beschäftige dich wenigstens in Grundzügen mit der Objektorientierung in JavaScript.

DOM-Manipulation mit JavaScript

  • Nutze querySelector() und querySelectorAll(), um komplizierte DOM-Zugriffe zu vereinfachen.
  • Vermeide direkte Änderungen am style-Attribut eines DOM-Elements.
  • Schalte stattdessen mit element.classList einzelne Stylesheet-Regeln ein oder aus.
  • Versuche, möglichst viele DOM-Manipulationen in einer zentralen Methode zu sammeln.
  • Nimm DOM-Manipulationen keinesfalls wo du gehst und stehst überall im JS-Code vor.
  • Nutze Frameworks wie jQuery nur, wenn du mit reinem JavaScript nicht weiter kommst.
  • Die Standardklassen von JavaScript können mehr als du denkst oder die Frameworks zugeben.

Nützliche Werkzeuge

  • Mache ausgiebigen Gebrauch von der JavaScript-Konsole und dem Debugger deines Browsers.
  • Nutze das von node.js bekannte npm, um die Abhängigkeiten in deinen Projekten zu verwalten.
  • Andere Werkzeuge wie Bower oder Browserify sind inzwischen schon nicht mehr modern.
  • Nutze Packer wie esbuild oder Parceljs, um die Ladezeiten deiner Seiten zu optimieren.
  • Nutze sie außerdem, um deinen JavaScript-Code in sauber gekapselt Module zu teilen.
  • Lerne aber erst die Sprache selbst und beschäftige dich erst dann mit den Werkzeugen!
