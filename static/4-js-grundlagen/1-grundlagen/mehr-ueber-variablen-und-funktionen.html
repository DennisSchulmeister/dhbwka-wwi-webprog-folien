Im Vergleich zu anderen Programmiersprachen besitzt JavaScript nur eine sehr begrenzte Anzahl an Datentypen und auch die neue Syntax zur Definition einer Funktion ist sicher etwas gewöhnungsbedürftig. Im Vergleich zu anderen Programmierprachen ist JavaScript deshalb aber nicht weniger flexibel, wie insbesondere das Video zeigt.

  • Boolean: Einfache Flags, die nur true oder false sein können.
  • Null: Kennt nur den Wert null.
  • Undefined: Standardwert, den alle nicht vorhandenen Variablen zurückliefern.
  • Number: Der einzige Zahlentyp in JavaScript. Entspricht einer 64-bit Fließkommazahl.
  • String: Zeichenketten, genau wie in Java auch.
  • Object: Zusammengesetzte Datentypen ähnlich den Objekten in Java.
  • Symbol: Besonderer Datentyp, mit dem das fehlende private-Schlüsselwort in JavaScript emuliert werden kann.
JavaScript ist eine schwach typisierte sowie dynamisch typisierte Sprache. Es gibt daher nur wenige, eingebaute Datentypen und der Typ einer Variable kann sich durch Zuweisung eines neuen Werts jederzeit ändern.
Globale Variablen sind in Wahrheit Attribute des window-Objekts.

Alte Syntax mit dem Schlüsselwort function:

function halloWelt(name, alter) { return `Hallo ${name}. Du bist ${alter} Jahre alt.`; }

Für neuen Code empfohlene Schreibweise:

let halloWelt = (name, alter) => { return `Hallo ${name}. Du bist ${alter} Jahre alt.`; };

Oder noch kürzer:

let halloWelt = (name, alter) => return `Hallo ${name}. Du bist ${alter} Jahre alt.`;

Oder am kürzesten:

let halloWelt = (name, alter) => `Hallo ${name}. Du bist ${alter} Jahre alt.`; Das Video erklärt die Besonderheiten, die bei der Definition und Verwendung von Variablen in JavaScript zu beachten sind. Darüber hinaus erklärt es die unterschiedlichen Syntaxen zur Definition von Funktionen im Detail.

Dynamische, schwache Typisierung

Wie auf der vorherigen Seite beschrieben, lassen sich Variablen in JavaScript viel einfacher verwenden als in Java. Man muss sie nicht wirklich deklarieren und ihr Datentyp ergibt sich einfach aus ihrem Inhalt. Streng genommen ist es sogar so, dass Variablen in JavaScript gar keinen Typ haben, sondern nur ihr Inhalt. Deshalb kann sich der Typ auch jederzeit ändern, da man in eine Variable ja jederzeit einen neuen Wert schreiben kann.

Das ist anders als in Java, wo man den Typ einer Variable von Anfang an festlegen muss und sich dieser dann auch nicht mehr ändern kann. Java nennt man daher statisch typisiert, 🐻 während JavaScript dynamisch typisiert ist. 🐀

Dennoch gibt es natürlich Datentypen in JavaScript. Allerdings gar nicht so viele. Genauer gesagt sind es sogar erstaunlich wenige, gerade mal sieben Stück. Und viele davon verwendet man auch nicht so oft. Für Variablen benötigt man in der Regel eigentlich nur die folgenden Typen:

  • Boolean: Kennst du aus Java. Ein Boolean kann nur true oder false sein.
  • String: Kennst du ebenfalls aus Java. Ein String ist eine Zeichenkette, in der Unicode-Zeichen gespeichert werden.
  • Number: JavaScript hat tatsächlich nur diesen einen nummerischen Datentyp. Er entspricht dem double aus Java, da es sich um eine 64-bit Fließkommazahl handelt. Neben den üblichen Zahlen kann er noch die Werte +infinity, -infinity und NaN beinhalten.
  • Object: Das sind im Prinzip Objekte, wie du sie aus Java kennst. Jedoch werden sie anders erzeugt und gerade die Objektorientierung ist in JavaScript in gewisser Weiße speziell.

Das war's dann schon. Die anderen Typen benutzt man nur in ganz besonderen Ausnahmefällen, zum Beispiel um zu prüfen, ob eine Variable überhaupt definiert ist. Aus diesem Grund nennt man JavaScript auch eine schwach typisierte Sprache. 🚶 Java hingegen – du denkst es dir sicher schon – ist eine stark typisierte Sprache. 💪

Der Gültigkeitsbereich einer Variable

Hier schleppt JavaScript den meisten Ballast mit sich rum. 🗿 Denn ursprünglich waren alle Variablen in JavaScript globale Variablen. Eine einmal verwendete Variable ist daher im gesamten JavaScript-Code gültig. Selbst wenn sie innerhalb einer Funktion steht, wie das folgende Beispiel zeigt:

let random = () { zufallszahl = 4; // Durch Würfeln ermittelt // Ist daher garantiert zufällig // Vgl. https://xkcd.com/221/ return zufallszahl; } let zeigeZufallszahl = () { console.log(zufallszahl); } random(); zeigeZufallszahl();

Dieser Quellcode gibt tatsächlich die Zahl 4 aus, da die Variable zufallszahl nach dem Aufruf von random(); erhalten bleibt. Würde man stattdessen erst zeigeZufallszahl(); und dann random(); ausführen, wäre das Ergebnis undefined.

Technisch gesehen sind globale Variablen so realisiert, dass sie einfach am window-Objekt hängen. Die folgenden zwei Zeilen sind daher identisch:

meinName = "Hugo Boss"; window.meinName = "Hugo Boss";

Du siehst, mit Variablen musst du höllisch aufpassen. 👹 Gewöhne dir daher am besten gleich an, vor jede Variable let zu schreiben. Steht die Variable außerhalb einer Funktion, macht es kaum einen Unterschied. Aber steht sie innerhalb einer Funktion, kannst du dir sicher sein, dass es nicht so solchen Fehlern wie eben beschrieben kommt.

In altem JavaScript-Code (älter als 2016) findet man stattdessen auch noch das Schlüsselwort var. Es bewirkt im Prinzip dasselbe wie let, schränkt aber den Gültigkeitsbereich einer Variable nur auf die gesamte Funktion ein. let hingegen begrenzt die Variable auf den aktuellen Code-Block. An einem Beispiel wird der Unterschied schnell klar:

function lonestar() { // Variable mit var, gibt "10" aus for (var i = 0; i < 10; i++) { … } console.log(i); // Variable mit let, wirft einen ReferenceError for (let j = 0; j < 10; j++) { … } console.log(j); }

Die Variable i bleibt nach der for-Schleife erhalten und beinhaltet den letzten Wert kurz vor Abbruch der Schleife. j hingegen ist nur auf die Schleife selbst begrenzt. Nach Verlassen des Schleifenkörpers wird die Variable wieder gelöscht.

Funktionen gestern, heute, morgen

Funktionen wurden in JavaScript die längste Zeit mit dem function-Schlüsselwort definiert. Zum Beispiel so:

function addiere(a, b) { return a + b; }

Das sieht zwar relativ ähnlich zu Java aus, hat aber doch ein paar gravierende Unterschiede:

  • Java kennt Funktionen überhaupt nicht. In Java gibt es nur Methoden, die per Definition in einer Klasse stehen müssen.
  • Funktionen haben keine Zusätze wie public, static oder final.
  • Wenn eine Funktion einen Wert zurückliefert, wird dies nirgendwo kenntlich gemacht. Denn eine Funktion, in der die return-Anweisung nicht vorkommt, gibt automatisch den Wert undefined zurück.
  • Bei den Parametern wird ebenfalls nur der Name ohne Typ angegeben. Das passt natürlich in das allgemeine Bild, dass sich der Typ einer Variable jederzeit ändern kann und daher nicht angegeben wird.

Im Großen und Ganzen ist die alte Schreibwiese schon okay. Historisch bedingt verhalten sich die so deklarierten Funktionen aber in verschiedenen Fällen sehr umständlich. 2016 wurde daher eine neue Schreibweise eingeführt:

let addiere = (a, b) => { return a + b; };

Das Besondere ist dabei gar nicht mal die Schreibweise. Obwohl die neue Form den netten Vorteil hat, das sich einzeilige Funktionen sehr kompakt schreiben lassen:

// Ohne geschweifte Klammern aber mit return-Anweisung let addiere_mittel = (a, b) => return a + b; // Ohne geschweifte Klammern und ohne return-Anweisung let addiere_kurz = (a, b) => a + b;

Das Besondere daran ist, dass sich die so deklarierten Funktionen in manchen Fällen anders verhalten. Im Moment macht das noch keinen Unterschied für uns. Sobald wir aber anfangen, objektorientiert zu programmieren, solltest du dich an die neue Schreibweise gewöhnen. Denn gerade die this-Variable verhält sich in den neuen Funktionen viel mehr so, wie du es von Java her kennst. Ab hier verwenden daher nur noch die neue Form.

Eine Kleinigkeit sei hier noch gezeigt. Nämlich wie mit der neuen Schreibweise eine Funktion ohne Parameter definiert wird:

// Alte Schreibweise function sagHallo() { return "Hallo, Welt"! } // Neue Schreibweise let sagHallo = () => "Hallo, Welt!";

Hat die Funktion genau einen Parameter, können die runden Klammern entfallen:

let sagHallo = name => `Hallo ${name}!`;
