Hier ist ein weiteres Beispiel für den praktischen Einsatz von JavaScript: die Prüfung von Formulareingaben. Vermutlich sind Ihnen bereits ähnliche Formulare auf verschiedenen Webseiten begegnet. Häufig handelt es sich dabei um Kontaktformulare, über die Nachrichten an den Seitenbetreiber gesendet werden können. Es können jedoch auch beliebige andere Eingabefelder enthalten sein, die zur Weiterverarbeitung an den Server übermittelt werden.

Eine grundlegende Regel der Webentwicklung besagt, dass der Server alle empfangenen Daten zwingend validieren muss, um Sicherheitslücken zu vermeiden. Um die Benutzerfreundlichkeit zu erhöhen, sollten die Eingaben jedoch bereits vor dem Absenden clientseitig geprüft werden. Dadurch können fehlende oder falsche Eingaben erkannt und dem Nutzer vor dem Versand angezeigt werden.

Der HTML-Code

Formulare haben wir bisher noch nicht kennengelernt. Deshalb erfolgt hier eine kurze Erklärung, was die einzelnen HTML-Elemente bedeuten.

<form action="…" method="…">

Ein Formular fasst ein oder mehrere Eingabefelder zusammen, die zur Weiterverarbeitung an den Server geschickt werden können. Hierfür sendet der Browser eine HTTP-Anfrage an die im action-Attribut hinterlegte URL. method kann dabei entweder GET oder POST sein und legt fest, auf welche Art die Daten übertragen werden. Details dazu erfährst du, sobald wir uns mit HTTP auseinandersetzen.

<label>

Hiermit werden die Feldbezeichner definiert. Durch das for-Attribut wird dabei festgelegt, auf welches Feld sich der Bezeichner bezieht. Dies macht zwar keinen Unterschied in der Darstellung, ist aber für Screenreader und andere Ausgabegeräte eine wichtige Information.

<input>

Dieses Element definiert, wie der Name schon sagt, ein Eingabefeld. Das type-Attribut legt dabei fest, welche Daten das Feld versteht (text, email, phone, und so weiter).

<select>

Hiermit wird eine Dropdown-Liste mit vorgegebenen Auswahlmöglichkeiten definiert.

<textarea>

Dies ist ein mehrzeiliges Eingabefeld, in das der Anwender beliebig langen Text schreiben kann. Von Haus aus wird allerdings nur unformatierter Text unterstützt. Sollen stattdessen auch formatierte Eingaben erlaubt werden, geht dies nicht ohne zusätzliche Bibliotheken. Zum Beispiel: TineMCE oder CKEditor.

<input type="submit">

Das ist der Knopf, den der Anwender drücken muss, um das Formular an den Server zu schicken.

So wie hier gezeigt, werden nicht nur die Formulareingaben an den Server geschickt, sondern dabei auch eine neue Seite vom Server angefordert. Dies ist das historisch bedingte Standardverhalten von Formularen. Solleb nur die Daten an den Server geschickt werden, ohne die Seite zu verlassen, müssen Sie leider warten, bis wir uns AJAX anschauen.

Der JavaScript-Code

Die Verbindung zum JavaScript-Code erfolgt über das submit-Event, das das Formular wirft, sobald der Anwender es verschicken möchte. Hier haben wir es uns einfach gemacht, und rufen über das onsubmit-Attribut im HTML die JavaScript-Funktion validateForm() auf.

Das zu überprüfende Formular steht in der Variablen event.target. Dieses Objekt hat für jedes Eingabefeld ein gleichnamiges Attribut, dessen Name sich aus dem name-Attribut im HTML ergibt. Und dieses besitzt widerum ein value-Attribut für seinen Inhalt:

let validateForm = event => { let form = event.target; … // Vorname muss vorhanden sein if (form.firstname.value == "") { … } … }

Der Rest ist relativ einfach. Bei genauerer Betrachtung der Funktion wird deutlich, dass hier lediglich einige if-Abfragen hintereinander geschaltet sind, um die Inhalte der Formularfelder zu prüfen. Allerdings muss der Browser am Ende natürlich wissen, ob die Prüfung erfolgreich war oder nicht. Standardmäßig nimmt er dabei an, dass alles in Ordnung ist und das Formular abgeschickt werden kann. Um dies zu verhindern, wird am Ende der Funktion folgende Methode aufgerufen:

//if (!okay) { event.preventDefault(); //}

Anhand der Kommentare sehen Sie, dass dies eigentlich nur erfolgen sollte, wenn die Prüfung des Formulars fehlgeschlagen ist. Da wir hier aber nicht wirklich einen Server im Hintergrund haben, der mit den Eingaben dieses Beispiels etwas anfangen kann, wird die Methode hier immer aufgerufen.
