Wie Sie sehen, ist HTML wirklich ein einfaches Format. Auch ohne ausschweifende Erklärungen müssen Sie sich nur ein wenig das Beispiel anschauen und sehen sofort, was die wichtigsten Eigenheiten sind. Sicherheitshalber erklären wir es hier aber nochmal.

HTML ist eine sogenannte Markup Language (Auszeichnungssprache). Damit ist gemeint, dass HTML-Dateien einfache Textdateien sind, wie sie mit einem einfachen Texteditor (zum Beispiel Notepad) erstellt und bearbeitet werden können. Neben Buchstaben, Zahlen und Zeilenumbrüchen beinhalten sie noch für Mensch und Computer lesbare Steueranweisungen, die einzelnen Abschnitten eine Bedeutung zuweisen und dem Text dadurch eine Struktur geben. Weitere Beispiele für solche Sprachen sind:

  • TeX und LaTeX
  • ReStructuredText
  • Markdown
  • Textile
  • Wikitext
  • PostScript
  • Rich Text Format
  • …

Auszeichnungssprachen stehen im Gegensatz zu Binärdateien, wie sie von Microsoft Word, Libre Office und anderen Programmen erstellt werden. Denn diese lassen sich nicht in einem Texteditor öffnen und beinhalten auch keinen lesbaren „Quellcode“, der von Hand editiert werden kann. Die Syntaxregeln von HTML sind eigentlich ganz einfach. Es gibt eigentlich nur Tags (englisch „Tägs“ ausgesprochen, manchmal auch HTML-Elemente genannt), die in spitzen Klammern stehen, und Fließtext. Allerdings muss zwischen drei Arten von Tags unterschieden werden:

  • Öffnende Tags: Bestehen aus einem Befehl in spitzen Klammern und markieren den Anfang eines Bereichs. Zum Beispiel <title>, <body> oder <h1>.
  • Schließende Tags: Zu jedem öffnenden Tag gehört ein schließendes Tag mit genau demselben Namen. Vor dem Namen steht jedoch ein Schrägstrich. Sie markieren damit das Ende eines Bereichs. Zum Beispiel </body>. Bei der Reihenfolge ist auf eine korrekte Schachtelung zu achten. Das heißt die Tags müssen immer in der umgekehrten Reihenfolge geschlossen werden, wie sie geöffnet wurden.
  • Sich selbst schließende Tags: Ein Sonderfall sind die sich selbst schließenden Tags. Dabei handelt es sich um spezielle Tags, auf die kein schließendes Tag folgt. Oft erkennt man sie an einem Schrägstrich hinter dem Namen, der in HTML allerdings auch wegbleiben darf. Deshalb sind sowohl <br/> als auch <br> gültige, sich selbst schließende Tags.

Neben dem Namen eines Elements können (außer bei schließenden Tags) innerhalb der spitzen Klammer auch Attribute stehen, die sozusagen Parameter für den jeweiligen Befehl darstellen. Beispielsweise dient das Attribut href beim <a>-Element dazu, das Ziel eines Links zu definieren.

Die Groß- und Kleinschreibung der Tagnamen und Attribute ist egal. Inzwischen hat sich aber die Kleinschreibung als allgemeine Form eingebürgert, obwohl bis Anfang der 2000er-Jahre weitgehend Großschreibung vorherrschte. Things have changed.

Darüber hinaus hat jedes HTML-Dokument einen festen Aufbau, der in der folgenden Abbildung dargestellt ist:

Die erste Zeile sollte immer <!DOCTYPE html> lauten. Dadurch wird definiert, dass es sich um eine HTML5-Datei unter Ausnutzung aller aktuellen Browser-Features handelt. Früher wurde diese Zeile dazu genutzt, verschiedene, teilweise inkompatible HTML-Versionen zu kennzeichnen. Heutzutage ist dies glücklicherweise nicht mehr erforderlich.

Das erste richtige Tag einer HTML-Datei ist immer das <html>-Tag. Man nennt es auch das Wurzelelement, da sich dadurch immer eine Baumstruktur mit nur einem Oberknoten ergibt. Folgerichtig muss </html> immer das letzte Tag einer HTML-Datei sein. <head>…</head> und <body>…</body> sind dann in genau dieser Reihenfolge die einzigen beiden Elemente auf zweiter Ebene, da sie die (meist nicht sichtbaren) Metadaten sowie den anzuzeigenden Inhalt einer Seite kennzeichnen.

Mehr Regeln gibt es im Prinzip nicht, außer dass die Zeichen < und > nicht außerhalb von Tags vorkommen dürfen. Sie müssen stattdessen durch eine als „Entität“ bezeichnete Ersatzschreibweise ersetzt werden:

Zeichen Ersatzschreibweise
< &lt;
> &gt;
& &amp;

Darüber hinaus ist es immer eine gute Idee, den HTML-Code von Zeit zu Zeit mit einem Werkzeug wie den W3C Markup Validation Service zu überprüfen. Zwar sind die Browser sehr nachsichtig bei Syntaxfehlern. Es kann aber trotzdem zu unerwarteten Darstellungsfehlern kommen und auch die Code-Vervollständigung der meisten IDEs kommen nicht gut damit zurecht.
