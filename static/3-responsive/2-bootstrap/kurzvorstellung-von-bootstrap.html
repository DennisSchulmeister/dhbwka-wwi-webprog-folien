• Ursprünglich als Einmannprojekt bei Twitter gestartet, wurde Bootstrap 2011 unter MIT-Lizenz veröffentlicht.

    Bootstrap kennt zwei Container-Klassen namens container und container-fluid, die zur Definition spaltenbasierter Layouts verwendet werden können. Jeder Container besteht dabei aus einer oder mehrerer mit der Klasse row markierte Zeilen, die wiederum in bis zu zwölf col genannte Spalten unterteilt werden können.

    Obwohl alle Browser heutzutage maximal kompatibel zueinander sind, besitzen sie immer noch leicht abweichende Voreinstellungen bezüglich der Darstellung einiger HTML-Elemente. Beispielsweise nutzt jeder Browser eine etwas andere Standard-Schriftart sowie andere Abstände um Überschriften und Absätze herum, was zu geringfügigen Abweichungen in der Darstellung führen kann, wenn die Parameter nicht mit eigenen Werten überschrieben werden. Manche HTML-Elemente besitzen darüber hinaus von Haus aus entweder gar keine oder eine sehr altbackende Optik. Bootstrap übersteuert daher sämtliche Vorgaben der Browser zu Gunsten eines vordefinierten, modernen Erscheinungsbilds.

    Ursprünglich als Einmannprojekt zur Vereinheitlichung interner Webanwendungen bei Twitter erfunden, wurde Bootstrap schnell von anderen Entwickler*innen aufgegriffen und im Jahr 2011 als Open-Source-Projekt unter MIT-Lizenz der Allgemeinheit vorgestellt. Seither hat sich Bootstrap zu einem der beliebtesten Webframeworks für die Frontendentwicklung entwickelt, das auch heute noch in vielen Projekten genutzt wird. Im Gegensatz zu anderen Frameworks, die oft nach kurzer Zeit wieder von der Bildfläche verschwinden (oder wie jQuery nicht mehr benötigt werden), wurde Bootstrap inzwischen mehrmals neugeschrieben, um mit aktuellen Entwicklungen im Web Schritt zu halten. Auch wenn heute die Notwendigkeit für Frameworks nicht mehr so groß ist wie früher¹, bietet insbesondere Bootstrap in größeren Projekten nach wie vor viele Vorteile. Stellvertretend für eine ganze Reihe ähnlich gelagerter Frameworks² wollen wir uns daher die Programmierung mit Bootstrap an dieser Stelle genauer anschauen.

    Anfangs war Bootstrap vor allem für sein Grid-System bekannt, da sich damit leicht gängige Layouts, die zudem auch responsive sind, realisieren lassen. Inzwischen bietet es aber eine ganze Fülle an Funktionen, die nicht minder interessant sind:

    • Layout-Grid: Mit Hilfe des Grid-Systems von Bootstrap können spaltenbasierte Layouts definiert werden, deren Inhalte auf unterschiedlichen Geräten automatisch in unterschiedlichen Größenverhältnissen nebeneinander oder in maximaler Breite untereinander angeordnet werden.
    • Typografie: Bootstrap definiert einheitliche Vorgaben für Schriftarten, Farben und Abstände, um eine absolut identische Darstellung in allen Browsern sicherzustellen. Zusätzlich wird für HTML-Elemente wie <blockquote> oder <kbd>, die ohne eigenes Styling in jedem Browser etwas anders aussehen, eine einheitliche Formatierung vorgegeben.
    • Formulare: Für Benutzereingaben werden in HTML typischerweise Eingabeformulare mit den Elementen <form>, <input>, <select>, <button> usw. definiert. Ihre standardmäßige Darstellung entspricht jedoch längst nicht mehr aktuellen Vorstellungen, so dass diese in der Regel mit CSS umfangreich bearbeitet werden müssen. Bootstrap überschreibt die Vorgaben der Browser mit sinnvollen Werten und bietet eine Vielzahl von Hilfsklassen, um die Gestaltung selbst komplexer Formulare zu vereinfachen.
    • UI-Komponenten: Im Laufe der Zeit haben sich auch im Web verschiedene UI-Patterns herauskristallisiert, die immer wieder vorzufinden sind. Die obligatorische Kopfzeile mit dem Namen der Seite, Navigationspunkten und Suchfeld ist zum Beispiel auf vielen Seiten nicht mehr wegzudenken. Aber auch Dropdown-Menüs, Tabreiter, Karten, Akkordeons, Karussells, Spinner oder modale Popup-Fenster gehören inzwischen zum Standard-Repertoire, das ohne Framework jedes Mal aufs Neue implementiert werden müsste.
    • Vordefinierte CSS-Klassen: Die Entwicklung eigener Stylesheets ist durch Bootstrap auch deshalb häufig überflüssig, weil es für viele CSS-Anweisungen passende Klassennamen gibt, die im HTML-Code direkt verwendet werden können, um ein Element damit auszuzeichnen. Beispielsweise kann mit <div class="shadow-sm"> einem Element ein dezenter Schatten gegeben werden, ohne diesen in CSS definieren zu müssen. Oftmals kann dabei über den Klassennamen eingeschränkt werden, auf welchen Geräten die Darstellung zum Tragen kommen soll.

    Grundgedanke von Bootstrap ist, alle Funktionen durch vordefinierte CSS-Klassen zu implementieren, so dass in vielen Fällen lediglich der HTML-Code angepasst werden muss, um ein bestimmtes Layout zu erzielen. Eigene Stylesheets werden nur benötigt, wenn die Vorgaben von Bootstrap übersteuert werden sollen oder Bootstrap für ein Problem keine passende Lösung bietet. Wahlweise kann dann noch der enthaltene JavaScript-Code eingebunden werden, um die vordefinierten UI-Elemente ohne eigene Logik programmieren zu müssen „zum Leben zu erwecken“.³
