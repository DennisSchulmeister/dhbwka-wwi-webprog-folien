• Ursprünglich als Einmannprojekt bei Twitter gestartet, wurde Bootstrap 2011 unter MIT-Lizenz veröffentlicht.

    Bootstrap kennt zwei Container-Klassen namens container und container-fluid, die zur Definition spaltenbasierter Layouts verwendet werden können. Jeder Container besteht dabei aus einer oder mehrerer mit der Klasse row markierte Zeilen, die wiederum in bis zu zwölf col genannte Spalten unterteilt werden können.

    Obwohl alle Browser heutzutage maximal kompatibel zueinander sind, besitzen sie immer noch leicht abweichende Voreinstellungen bezüglich der Darstellung einiger HTML-Elemente. Beispielsweise nutzt jeder Browser eine etwas andere Standard-Schriftart sowie andere Abstände um Überschriften und Absätzen herum, was zu geringfügigen Abweichungen in der Darstellung führen kann, wenn die Parameter nicht mit eigenen Werten überschrieben werden. Manche HTML-Elemente besitzen darüber hinaus von Haus aus entweder gar keine oder eine sehr altbackende Optik. Bootstrap übersteuert daher sämtliche Vorgaben der Browser zu Gunsten eines vordefinierten, modernen Erscheinungsbilds.

Insgesamt decken die CSS-Hilfsklassen einen großen Teil von CSS-Anweisungen ab, so dass in vielen Fällen auf eigene Stylesheets verzichtet werden kann (zugunsten eines aufwändigeren und wenig übersichtlichen HTML-Codes).

    Ursprünglich als Einmannprojekt zur vereinheitlichung interner Webanwendungen bei Twitter erfunden, wurde Bootstrap schnell von anderen Entwickler*innen aufgegriffen und im Jahr 2011 als Open-Source-Projekt unter MIT-Lizenz der Allgemeinheit vorgestellt. Seither hat sich Bootstrap zu einem der beliebtesten Webframeworks für die Frontendentwicklung entwickelt, das auch heute noch in vielen Projekten genutzt wird. Im Gegensatz zu anderen Frameworks, die oft nach kurzer Zeit wieder von der Bildfläche verschwinden (oder wie jQuery nicht mehr benötigt werden), wurde Bootstrap inzwischen mehrmals neugeschrieben, um mit aktuellen Entwicklungen im Web schrittzuhalten. Auch wenn heute die Notwendigkeit für Frameworks nicht mehr so groß ist wie früher¹, bietet insbesondere Bootstrap in größeren Projekten nach wie vor viele Vorteile. Stellvertretend für eine ganze Reihe ähnlich gelagerter Frameworks² wollen uns daher die Programmierung mit Bootstrap an dieser Stelle genauer anschauen.

    Anfangs war Bootstrap vor allem für sein Grid-System bekannt, da sich damit leicht gängige Layouts, die zudem auch responsive sind, realisieren lassen. Inzwischen bietet es aber eine ganze Fülle an Funktionen, die nicht minder interessant sind:

    • Layout-Grid: Mit Hilfe des Grid-Systems von Bootstrap können spaltenbasierte Layouts definiert werden, deren Inhalte auf unterschiedlichen Geräten automatisch in unterschiedlichen Größenverhältnissen nebeneinander oder in maximaler Breite untereinander angeordnet werden.
    • Typografie: Bootstrap definiert einheitliche Vorgaben für Schriftarten, Farben und Abstände, um eine absolut identische Darstellung in allen Browsern sicherzustellen. Zusätzlich wird für HTML-Elemente wie <blockquote> oder <kbd>, die ohne eigenes Styling in jedem Browser etwas anders aussehen, eine einheitliche Formatierung vorgegeben.
    • Formulare: Für Benutzereingaben werden in HTML typischerweise Eingabeformulare mit den Elementen <form>, <input>, <select>, <button> usw. definiert. Ihre standardmäßige Darstellung entspricht jedoch längst nicht mehr aktuellen Vorstellungen, so dass diese in der Regel mit CSS umfangreich bearbeitet werden müssen. Bootstrap überschreibt die Vorgaben der Browser mit sinnvollen Werten und bietet eine Vielzahl von Hilfsklassen, um die Gesaltung selbst komplexer Formulare zu vereinfachen.
    • UI-Komponenten: Im Laufe der Zeit haben sich auch im Web verschiedene UI-Patterns herauskristalisiert, die immer wieder vorzufinden sind. Die obligatorische Kopfzeile mit dem Namen der Seite, Navigationspunkten und Suchfeld ist zum Beispiel auf vielen Seiten nicht mehr wegzudenken. Aber auch Dropdown-Menüs, Tabreiter, Karten, Akkordeons, Karussells, Spinner oder modale Popup-Fenster gehören inzwischen zum Standard-Repertoire, das ohne Framework jedes Mal aufs neue implementiert werden müsste.
    • Vordefinierte CSS-Klassen: Die Entwicklung eigener Stylesheets ist durch Bootstrap auch deshalb häufig überflüssig, weil es für viele CSS-Anweisungen passende Klassennamen gibt, die im HTML-Code direkt verwendet werden können, um ein Element damit auszuzeichnen. Beispielsweise kann mit <div class="shadow-sm"> einem Element ein dezenter Schatten gegeben werden, ohne diesen in CSS definieren zu müssen. Oftmals kann dabei über den Klassennamen eingeschränkt werden, auf welchen Geräten die Darstellung zum Tragen kommen soll.

    Grundgedanke von Bootstrap ist, alle Funktionen durch vordefinierte CSS-Klassen zu implementieren, so dass in vielen Fällen lediglich der HTML-Code angepasst werden muss, um ein bestimmtes Layout zu erzielen. Eigene Stylesheets werden nur benötigt, wenn die Vorgaben von Bootstrap übersteuert werden sollen oder Bootstrap für ein Problem keine passende Lösung bietet. Wahlweise kann dann noch der enthaltene JavaScript-Code eingbeunden werden, um die vordefinierten UI-Elemente ohne eigene Logik programmieren zu müssen „zum Leben zu erwecken“.³

    Auf dieser Seite finden sich ein ausführlicher Screencast zur Vorestellung von Bootstrap (inklusive praktischer Demonstration) sowie ein paar Beispiele zum gebotenen Funktionsumfang. Wie immer wird das Anschauen des Videos sehr empfohlen, um auch die Inhalte der folgenden Seiten besser nachvollziehen zu können!

    ¹ Frameworks wie jQuery entstanden, um die vielen kleinen Inkompatibilitäten zwischen den Browsern auszugleichen oder Funktionen bereitzustellen, die mit reinem HTML, CSS und JavaScript nur umständlich zu realisieren waren. Inzwischen sind die Browserkriege zum Glück längst vorbei, so dass Abweichungen lediglich bei ganz aktuellen Standards vorkommen, die noch nicht final ratifiziert wurden, aber bereits als Vorabversion in den Browsern implementiert sind, um Erfahrungen damit zu sammeln. Auf diese Weise sind auch immer mehr Funktionen nach HTML, CSS und JavaScript zurückgeflossen, wodurch komplexe Webanwendungen zunehmend ohne Frameworks auskommen. Frameworks können aber immer noch sinnvoll sein, um bestimmte Aufgaben zu vereinfachen, den Quellcode zu strukturieren oder komplexe UI-Elemente zur Verfügung zu stellen.

    ² Genauer gesagt schauen wir uns hier die Entwicklung mit CSS-Frameworks an, die zum größten Teil aus vordefinierten Stylesheets mit optionalem JavaScript-Code bestehen, um die Gestaltung bestimmter Layouts zu vereinfachen.     Paketverwaltung

  • In der professionellen Webentwicklung werden häufig Package Manager genutzt.
  • Beispiele hierfür sind der Node Package Manager oder Yarn.
  • Diese laden alle benötigten Bibliotheken und Frameworks aus einem zentralen Repository.
  • Zusätzlich wird dann noch ein Bundler wie Webpack oder Parcel benötigt.
  • Denn der Package Manager lädt die Pakete nur herunter. Der Bundler kopiert die Dateien in das Projekt¹.
  • Sind beide Voraussetzungen gegeben, kann Bootstrap mit einem Befehl wie dem folgenden installiert werden:
    • npm install bootstrap

    ¹ Dies ist eine stark vereinfachte Darstellung. Bundler bauen aus dem Quellcode einer Anwendung sowie den Quellcodes aller benötigten Bibliotheken so genannte Bundles, die vom Browser geladen und ausgeführt werden können. Auf diese Weise wird nicht nur die Integration externer Bibliotheken vereinfacht, da ihre Dateien nicht manuell in das Projekt kopiert werden müssen. Auch die Ladezeiten können optimiert werden, indem viele kleine Dateien zu einer größeren Datei zusammengefasst und anschließend minifiziert werden. Immer besser funktioniert dabei auch das so genannte „Tree Shaking“, durch das alle nicht benutzten Teile aus dem Quellcode entfernt werden.

    Import Maps

    Ein aktuell noch in Enstehung befindlicher Standard sind Import Maps, mit denen die Verwaltung externer Abhängigkeiten in der Frontend-Entwicklung künftig deutlich vereinfacht wird. Der Einsatz von Package Managern und Bundlern wird dadurch in vielen Projekten überflüssig werden. Da der Standard aber noch nicht ratifiziert wurde (Stand: September 2022), wird er derzeit nicht von allen Browsern unterstützt. Siehe Can I Use: Import Maps.

    Lediglich zwei Dateien werden benötigt, um Bootstrap in ein Projekt einzubinden: Das Bootstrap-Stylesheet und optional der dazugehörige JavaScript-Code. Sollen die vordefinierten UI-Elemente von Bootstrap nicht genutzt bzw. ihre Logik von Hand ausprogrammiert werden, genügt sogar nur das Stylesheet. Beide Dateien werden von den Bootstrap-Entwicklern anhand der Quellcodes von Bootstrap zusammengebaut und minifiziert, um die Ladezeiten zu optimieren. Das Framework kann somit leicht eingebunden werden, wobei hierbei drei Alternativen zur Verfügung stehen:

    1. Content Delivery Network: Am einfachsten ist die Einbindung über ein Content Delivery Network (kurz: CDN), da hierfür leidglich zwei Zeilen im HTML-Code ergänzt werden müssen. Die Dateien werden dabei von den weltweit gespiegelten Servern des Content Delivery Network geladen.
    2. Manueller Download: Will man sich nicht von fremdbetriebenen Servern abhängig machen, oder soll die Seite auch ohne permanente Internetverbindung ausführbar sein, können die zu integrierenden Dateien auch manuell heruntergeladen und in das eigene Projekt übernommen werden.
    3. Paketverwaltung: Je mehr Bilbiotheken und Frameworks in einem Projekt genutzt werden und je mehr diese von anderen Bibliotheken abhängen, desto aufwändiger und fehleranfälliger ist es, diese im Internet zu suchen und in das Projekt zu übernehmen. In vielen Projekten übernimmt diese Aufgabe heute daher ein Werkzeug zur Paketverwaltung.

    Auf dieser Seite werden die ersten beiden Alternativen vorgestellt, wobei von diesen meist die Variante mit dem Content Delivery Network zu bevorzugen ist. Denn auf diese Weise können Synergieeffekte mit anderen Seiten genutzt werden, in denen dieselbe Bootstrap-Version zum Einsatz kommt, da die Dateien dann ohne Zeitversatz aus dem Browser-Cache geladen werden. Außerdem haben Bundler und Werkzeuge zur Paketverwaltung das manuelle Suchen und Herunterladen von Bibliotheken inzwischen weitgehend verdrängt, so dass dies heutzutage nur noch in speziellen Fällen notwendig ist. Da hierfür aber umfangreiche Werkzeuge benötigt werden, die wir bisher noch nicht betrachtet haben, fehlt diese Möglichkeit hier.

    Responsive Webdesign

    • Fange immer mit der mobilen Darstellung an und arbeite dich schrittweise hoch.
    • One size doesn't fit all! Versuche daher nicht, dasselbe Layout auf allen Geräteklassen umzusetzen.
    • Nutze stattdessen Media Queries, um einzelne CSS-Eigenschaften nur für große Bildschirme zu aktivieren.
    • Ordne auf kleinen Bildschirmen die wichtigsten Elemente untereinander und maximal breit an.
    • Nutze den horizontalen Platz auf großen Geräten, um bestimmte Elemente nebeneinander anzuordnen.
    • Wähle für jede Geräteklasse eine angenehm lesbare Schriftgröße.
    • Vermeide verspielte Schmuckschriften, da sie auf mobilen Geräten nur schwer lesbar sind.
    • Versuche, immer den einfachsten Code zu schreiben, der dich zum Ziel bringt.
    • Prüfe falls möglich Eigenschaften wie die Anzahl darstellbarer Zeichen anstelle absoluter Pixelgrößen.
    • Blende alle überflüssigen Seitenleisten, Navigation, Fußzeile und Hintergründe aus, wenn deine Seite gedruckt wird.

    CSS-basierte Layout Grids

    • Erlerne die Nutzung CSS-basierter Layout-Grids wie das von Bootstrap.
    • Gewöhne dir insbesondere an, sie konsequent einzusetzen.
    • Prüfe aber dennoch, ob die Darstellung auf allen Geräteklassen deinen Vorstellungen entspricht.
    • Insbesondere Abstände wie Padding und Margin müssen mit Media Queries weiterhin justiert werden.
    • Wenn sich ein besonders komplexes Layout damit nicht darstellen lässt, überlege dir ein einfacheres.

    Sonstige Tipps und Tricks

    • Schaue dir möglichst viele mobile Apps und gut gestaltete Webseiten an, um davon zu lernen.
    • Mache dich auch mit anderen CSS-Layoutmodulen wie „Flexbox“ oder „Grid“ vertraut.
    • Probiere unterschiedliche CSS-Frameworks aus und versteife dich nicht auf ein einzelnes.
    • Wähle stattdessen für jedes Projekt das passende Framework aus. Es muss nicht immer Bootstrap sein.
    • Oder nutze für kleine bis mittlere Anwendungen gar kein Framework, wenn es keinen Mehrwert bietet.

    Hier nochmal das Wichtigste in aller Kürze. Auf dieser Seite haben wir wie immer ein paar allgemeine Tipps zusammengestellt, worauf du beim Webdesign achten solltest.
